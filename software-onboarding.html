Software Engineer Onboarding

A ground-zero path to a productive contributor on the team's robot control software — from no programming at all to opening your first reviewed pull request. Every resource below is free and current.

Start point: little/no coding Target: ship a reviewed PR Pace: ~6 weeks part-time Cost: $0 — all free Stack: Java 8 · Android · FTC SDK

How to use this. Work the phases in order — each assumes the one before it. The Git track runs in parallel: start it in Week 2 and use it for everything after. You are not expected to master a topic before moving on; you are expected to be able to follow along in the codebase. Pair with your assigned mentor early and often. On-robot testing is done by the Product Owner — your loop is write, build, get reviewed.

The Path

PHASE00

Setup & Orientation

Day 1 · ~2–3h Core

Get accounts, tools, and the repository on your machine — and read where you've landed. Do not write code yet; just get everything opening cleanly.

  • Create a GitHub account & get invited to the team setup · 15m GitHub — your identity for every change you make.
  • Install the toolchain: JDK, Android Studio, Git setup · 1–2h Local — follow the FTC "Installing Android Studio" guide (it pairs Studio with the right JDK), or the official Android Studio install guide. Then clone the repo, open it in Android Studio, and let Gradle finish syncing once.
  • Read the team README and Engineering Process read · 45m In-repo — README.md and doc/engineering-process.md. Orientation only; don't try to absorb it all.
PHASE01

Programming Foundations

Week 1 · ~8–12h Core

Learn what a program is — variables, conditionals, loops, functions — in a low-noise language before Java's syntax piles on. These ideas transfer directly.

  • Intro to Python Fundamentals interactive · self-paced Khan Academy — runs in the browser, zero setup, assumes no experience. Python teaches the concepts cleanly; you'll switch to Java next.
PHASE02

Java & Object-Oriented Programming

Weeks 2–3 · ~20–25h Core

The whole codebase is Java. Learn the language, then the object-oriented model (classes, objects, inheritance, interfaces, polymorphism) — this is the single most important phase.

  • Learn Java Programming (v17) video · 4h freeCodeCamp — one sitting, no signup: variables through arrays, ending in OOP. Watch first.
  • Learn Java interactive · ~17h Codecademy (free course) — hands-on; the OOP unit has you write your own classes, which is where it sticks. Ignore the Pro upsell.
  • Learn Java for FTC (free PDF — direct download) book · self-paced Alan G. Smith — the bridge: Java taught through motors, servos, sensors, gamepads, and OpModes. Read as you enter Phase 5.
PHASE03

Git & GitHub

From Week 2 · ~3–4h Parallel

Version control and the pull-request workflow — how every change on this team is made, reviewed, and merged. Start alongside Java; you'll use it for the rest of your time here.

  • Introduction to GitHub interactive · <1h GitHub Skills (official) — learn repos, branches, commits, and opening a PR by doing it in a real repo. Best starting point.
  • Review Pull Requests interactive · <30m GitHub Skills (official) — requesting a review, suggesting changes, approving — the collaboration half of PRs.
  • Resolve Merge Conflicts interactive · <30m GitHub Skills (official) — what causes conflicts and how to fix them without fear.
  • Read the team Git Protocol read · 30m In-repo — .claude/skills/git-protocol. Our branch naming, commit, and PR rules. Follow it exactly.
PHASE04

Android Studio, Deploying & Debugging

Weeks 3–4 · ~8–10h Core

The robot code is a Java Android app. Learn the editor, build and install the APK onto the Control Hub, connect over ADB, read the logs when something breaks, and watch live data on the dashboard.

  • Creating and Running an OpMode docs · ~30m FTC (official) · Java — Studio is already installed and synced from Phase 0; here you open the robot project, then create, build, and install your first OpMode APK to the Robot Controller.
  • Using Android Studio guide · ~20m gm0 · Java — the IDE layout, the Gradle build, deploying to the Control Hub over USB or wireless, and a first look at ADB and logcat.
  • Build and run your app docs · reference Android (official) — language-neutral reference for what the Run button does and where the built APK lands.
  • Gradle — Getting Started docs · ~1h Gradle (official) — what Gradle is, plus tasks, dependencies, and the ./gradlew wrapper. This is the tool behind assembleDebug; our build files are Groovy .gradle (build.dependencies.gradle and TeamCode/build.gradle).
  • Managing a Control Hub — wireless ADB docs · ~15m FTC (official) — the authoritative steps to reach the Control Hub over Wi-Fi so you can deploy and pull logs without a cable.
  • Android Debug Bridge (adb) reference · ~30m Android (official) — the command reference: adb connect, adb devices, and adb pull to copy DataLogger CSV files off the hub.
  • Common Issues + Logcat guide + reference gm0 · Android (official) — read a crash log and stack trace by example, then the definitive logcat reference for filtering the crash buffer.
  • FTC Dashboard — Getting Started + Features docs · ~30m ACME Robotics — connect in a browser, then plot values over time, draw the field overlay, and tune @Config parameters live.
  • Panels — Telemetry docs · ~20m Bylazar — our advanced dashboard: field view, telemetry, and live graphing. Read after FTC Dashboard.
On our robot We build with ./gradlew assembleDebug and deploy the APK to the REV Control Hub. Pull logs with adb; watch live data on FTC Dashboard (port 8080) and Panels (port 8001). You'll learn our exact flow with your mentor once you can build cleanly.
PHASE05

The FTC Robotics Stack

Weeks 4–5 · ~10–15h Core

Now the domain: how FTC robot code is structured (OpModes, hardware mapping, gamepads) and the two libraries this robot relies on for autonomous movement.

  • Game Manual 0 — Software tutorials · ~1–2h gm0 (community) — the most-recommended free FTC learning resource. Start with the "Getting Started" software pages.
  • Official FTC Documentation docs · reference FIRST (official) — authoritative install + first-OpMode guide, always current for the active season.
  • Getting Started Programming your FTC Robot in Java video · intro YouTube — a watch-along first OpMode if you prefer video before docs.
  • Our hardware & safety rules read · 30m README § Wiring — the wiring table that maps each motor and sensor name to a real port. Two rules: the names in code must match the Robot Configuration File exactly — renaming one breaks the robot — and you never run OpModes on the physical robot yourself; the Product Owner does that.
  • Get Started with Pedro Pathing + docs video + docs Pedro Pathing — our autonomous path-following library. The Nov 2025 setup video matches our version.
  • NextFTC Guide docs · ~1–2h NextFTC (official) — our command-based library. Documentation-first (no video series yet); code-along in Java.
Our versions FTC SDK 11.1.0 · Pedro Pathing 2.0.5 · NextFTC 1.1.0. When docs and our code disagree, our pinned version wins — read the source for the version we use.
PHASE06

Our Codebase & First PR

Weeks 5–6 · ongoing Core

Turn general knowledge into this robot. Learn how our software is organized, our rules, and then ship a small change end to end.

  • Architecture: the control loop & coordinate systems read · 2h README § Software Architecture — the 50 Hz five-phase state-machine loop, the subsystems, and FTC (mm/degrees) vs Pedro (inches/radians) coordinates. You work in the newer NextFTC command-based, modular-subsystem code — each subsystem is its own class. An older single-file design still lives in the repo, but it's legacy; new work doesn't go there.
  • Coding Conventions read · 30m README § Coding Conventions — no-allocation hot paths, no magic numbers, short single-purpose methods, comprehensive comments.
  • Real-time constraints (advanced) read · advanced README § Performance — why we avoid creating objects and doing extra hub reads inside the ~50 Hz loop: object creation causes stutter-inducing garbage-collection pauses, and each hub read is a slow round-trip. Save this for after your first PR.
  • The PBI lifecycle & Definition of Done read · 30m doc/engineering-process.md — how work flows: code changes happen only in the Implementation stage; a PR isn't done until the PO accepts it.
  • Running the unit tests hands-on · 30m In-repo — ./gradlew :TeamCode:testDebugUnitTest. See TeamCode/src/test/README.md for the harness.
  • Capstone — your first PBI guided · 1 week With a mentor — pick up a small starter task, branch, implement, get it reviewed, open a PR. This is the finish line.

Control Software Concepts

The ideas the codebase is built on. Dip into these while working through Phases 5–6 — they explain why the subsystems look the way they do. Video where a good one exists; two are best learned from short articles, and that's flagged.

  • The control loop: sense → decide → act + why it runs at a fixed rate articles · ~20m gm0 · Game Programming Patterns — read inputs, decide, then act, repeated ~50 times a second. No strong beginner video exists here, so it's text. This is the shape of every loop in the code.
  • State machines + Mealy vs Moore video · ~20m YouTube · Neso Academy — states and transitions, then the Moore-vs-Mealy distinction. Our robot software is a Moore machine: outputs depend only on state.
  • Command-based programming + WPILib explainer video + docs FRC 0 to Autonomous · WPILib — behavior organized into commands and subsystems that get scheduled, running in sequence or in parallel. The model behind our NextFTC library.
  • Closed-loop control: PID video · ~10m Brian Douglas — correcting error toward a target, with almost no math. How the shooter holds a set flywheel speed.
  • Feedforward (and PIDF) + flywheel example docs · ~15m gm0 · WPILib — predicting the output you need instead of only reacting to error: the "F" in the shooter's PIDF. gm0 covers PID and feedforward together, no calculus. No clean beginner video exists here.
  • Odometry & localization + gm0 concept page video · ~10m The Clueless (FTC) · gm0 — how the robot tracks its position and heading from wheel encoders and the IMU. Our Pinpoint does this with sensor fusion.
  • Mecanum kinematics + gm0 holonomic drives video · ~9m Lesics · gm0 — how four angled-roller wheels combine into forward, strafe, and turn. This is our drivetrain.

Conceitos de Software de Controlo

Os conceitos por trás do código. Onde não existe recurso em português, fica indicado que se deve usar a versão em inglês.

  • O loop de controlo: sentir → decidir → agir artigo · PT-BR Escola LBK — ler sensores, decidir e depois atuar, repetidamente. É a forma de todos os ciclos do código.
  • Máquinas de estados (Moore e Mealy) artigo · PT-BR B. Albertini (USP) — estados e transições, e a diferença Moore vs Mealy. O nosso software é uma máquina de Moore.
  • Programação baseada em comandos só em inglês Sem versão em português — vê a versão em inglês (WPILib / NextFTC).
  • Controlo em malha fechada (PID) vídeo · PT-BR YouTube — corrigir o erro até ao valor desejado. É como o lançador mantém a rotação do volante.
  • Feedforward (controlo antecipatório) vídeo · PT-BR YouTube — prever a saída necessária em vez de só reagir ao erro: o "F" do PIDF.
  • Odometria e localização + Insper documentação · PT-BR stemOS · Insper — como o robô sabe onde está, a partir dos encoders e do IMU.
  • Cinemática Mecanum documentação · PT-BR stemOS — como as quatro rodas de roletes combinam para andar em frente, deslizar e rodar.
